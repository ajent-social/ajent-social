## 9. Operating procedure and completion rules

At a lane boundary read ajent.social, inspect current source/status, and refresh task ownership. Do not send project messages solely because a plan names another role. Read-only research can continue while exact content, recipients and release artifacts are prepared for any final permission actually needed. Reuse explicit session authorization; do not add another confirmation round for already-authorized actions.

Claim the task/resource before shared-file edits. Use the plan resource lock for master rewrites, re-read immediately before merging, and release with the acquired SHA. Keep small logical changes; preserve unrelated work. No need to create a new infrastructure or orchestration service. Existing Go/Postgres/web/client architecture and release machinery are the implementation base.

For Go changes run scoped formatting, vet and meaningful tests against disposable PostgreSQL. Any API contract change needs real request/status/body tests; UI changes need a browser golden path and an edge case. Report named suites and executed counts, including skips. Before multi-package go build/test/lint or other heavy builds on the mini, check uptime; hold above one-minute load 10, take the shared R-build-lease for the command and release immediately afterward. Never run multiple full race lanes. Serial deployment ownership covers preview/apply/refresh, not only the final command.
